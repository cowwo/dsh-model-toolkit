# 一个包、一个插件条目

状态：已接受（accepted）

合并后的「模型工具包」只发布一个包（`dsh-model-toolkit`），并且只挂一个插件条目（插件 id `model-toolkit`）。代价是浏览器侧只会出现一个插件条目，无法再分别禁用「能力编辑」和「徽章与余量」两半功能；补偿办法是在插件内部提供两个设置开关。

## 背景

合并前有两个各自独立发布、各自有用户的插件：

| 插件 | 做什么 | 用户的动作 |
| --- | --- | --- |
| 模型能力管理（`dsh-model-fit` 0.2.3） | 在设置页给自定义模型写能力（图片输入、推理强度、线路级系统消息角色），支持从目录模型一键「继承自…」 | 先配好，再聊天 |
| 输入框显示提供商（`dsh-provider-info` 0.17.0） | 在输入框模型座左侧显示徽章，悬停出信息浮层；设置页另有一块「提供商信息与余量」 | 聊天时随时看 |

两者服务的是同一条用户动作链：用户先要知道"我现在用的是哪条线路、这个模型还能用多少"，再去调"这个模型有哪些能力"。分成两个插件意味着两次安装、两个设置入口、两条发布线，用户还得自己把这两件事联系起来。所以决定合并。

合并要回答的第一个问题是"合并的单位是什么"：代码放几个包、DSH 里挂几个插件条目。这个选择一旦发布就很难回头——插件条目是用户可见的身份，改它等于让用户重新理解一遍自己装了什么。

## 考虑过的方案

### 方案 A：一个包挂两个插件条目（放弃）

DSH 官方插件 `dsh-tool-subagent` 就是这么做的，所以这条路是通的。好处很直接：两半功能在插件页各占一行，用户可以只启用「能力编辑」、不启用「徽章与余量」，控制粒度最细，合并后也不会丢掉原来"两个插件"的灵活性。

放弃的理由：合并的诉求是"用户装一个东西就得到整套体验"，两个条目会让插件页多出一行、多出一个开关，用户还得理解这两半是什么关系；而两半在界面上本来就长在一起（同一个设置页、同一个输入框），拆开之后并没有一条清晰的边界能解释"为什么这是两个插件"。另外，浏览器侧的插件身份跟着包名走，两半的界面又都在浏览器侧——就算挂了两个条目，浏览器侧也很难真正给出两套独立身份，方案 A 最主要的那条好处打了折扣。

### 方案 B：一个包、一个插件条目（选中）

插件页只有一行，两半功能都在这一个插件里。原来"分别禁用"的需求改用插件内部的设置开关满足：「能力编辑」可关、「徽章与余量」可关。

### 方案 C：一个仓库、两个包（放弃）

保留两个独立包（各自的包名、版本、发布流程），只是放进同一个仓库共享代码。

好处是两半的插件身份、版本节奏、启用/禁用完全保持独立，等于"合并了开发，没合并交付"。

放弃的理由：对用户来说等于什么都没变——还是要装两个、更新两次、盯两个版本号；对本项目来说发布流程直接翻倍（每个包都要走一遍 npm 双包发布），而合并的初衷恰恰是让用户少装一个东西。

## 决策

采用方案 B：一个包（`dsh-model-toolkit`）、一个插件条目（插件 id `model-toolkit`）。

"分别禁用"这件事不消失，只是换了位置：从 DSH 的插件开关降级为插件自己的设置开关——「能力编辑」可关、「徽章与余量」可关。

## 后果

**好的**

- 用户只装一个、只更新一个，插件页只有一行，不需要理解两半的关系。
- 两半共享同一份代码与同一个设置页，协作不用跨插件通信；将来的联动（例如浮层里直接显示当前模型的能力来源）也没有插件边界挡着。
- 发布只有一条线：一个 tag 触发一次发布，产出双包（裸名 + scope 名）。这两个名字指的是同一个包，不是两个插件。
- 插件内部开关比插件级开关更灵活：将来想加第三块功能，或者想让开关按场景组合，都不用动包结构。

**坏的**

- **浏览器侧只有一个插件条目，无法再分别禁用两半功能。** 这是选方案 B 时明确付出的代价：用户想要"只要徽章、不要能力编辑"，只能进设置页找开关，不能像以前那样在插件页直接不启用。而"关掉整个插件"是另一种粒度，中间没有别的档位。
- 补偿开关是插件自己的实现，不是 DSH 的插件机制：插件页上看到的仍然是"一个插件、一个开关"。用户不一定知道设置页里还有两个开关，发现成本比插件页高。
- 两半的生死绑在一起：插件加载失败，两半一起不可用；升级出问题，两半一起回滚。
- 将来若某一半需要独立发布（例如徽章那半想给别的插件复用），得重新拆包，并承担一次用户可见的身份变更。

**留痕**

- 如果未来要回到方案 A，改动的是包内插件条目的声明方式，用户侧表现为"插件页从一行变两行"，需要写清楚迁移说明。
- 方案 A 的那条好处（插件级分别禁用）在方案 B 里没有等价物，只能靠设置开关近似，不要在后来的文档里把它说成"完全等价"。
